# ConvertKit AdSense 上线前页面检查清单

**适用项目：** ConvertKit（`lovexiaoyue.cc.cd`）  
**文档目的：** 在申请或启用 Google AdSense 前，逐页检查内容价值、政策合规、隐私同意、SEO、用户体验和广告位风险。  
**建议状态：** 每项完成后记录证据链接、截图或测试日期，不要只凭主观判断标记完成。

> 重要说明：通过所有检查并不等于 Google 一定批准 AdSense，也不代表未来不会产生政策问题。Google 会持续更新发布商政策，最终应以 [AdSense Program policies][1]、[Google Publisher Policies][2] 和 [EU user consent policy][3] 为准。

## 一、上线阻断项

以下任一项未完成，都建议暂缓申请或暂缓展示个性化广告。

| 检查项 | ConvertKit 的具体要求 | 状态 | 证据或备注 |
|---|---|---:|---|
| 网站可访问性 | 首页、主要转换器、格式工具、指南和法律页面均能通过 HTTPS 正常打开；不能存在大面积 5xx、空白页或错误重定向。 | ☐ | |
| 内容可见性 | 主要内容必须在普通用户访问时可见，不能要求登录、订阅或点击广告才能使用基本转换功能。 | ☐ | |
| 原创与实用价值 | 每个转换器页面不只是输入框和结果，还应解释单位、公式、示例、精度、反向换算和适用场景。Google Search 强调 people-first、完整和有实质价值的内容。[4] | ☐ | |
| 法律页面 | `/privacy`、`/terms`、`/cookie-policy`、`/about`、`/contact` 已上线，内容真实、可访问且互相链接。 | ☐ | |
| 隐私披露 | 隐私政策明确说明 AdSense、Cookie、个性化广告、分析工具、数据处理目的、第三方供应商和用户选择权。 | ☐ | |
| 同意管理 | 面向 EEA、英国和瑞士用户时，已配置符合 Google 要求的 CMP 或等效同意流程，并能记录、撤回和更新选择。[3] | ☐ | |
| 真实流量 | 没有购买低质量流量、付费点击、激励点击、垃圾邮件导流或自动化刷量。Google 禁止人为增加展示和点击。[1] | ☐ | |
| 点击行为 | 站长、员工、测试人员和合作方不会点击自己的广告；测试使用浏览器开发工具或广告预览方式，不点击线上广告。 | ☐ | |
| 发布商账号 | AdSense 账号、收款人身份、地址、域名所有权和税务资料使用真实且一致的信息。 | ☐ | |
| robots 与 sitemap | `robots.txt` 不阻止主要内容和资源；`sitemap.xml` 可访问；生产 robots 的 Cloudflare Managed content 已人工复核。 | ☐ | |
| 资源完整性 | HTML、CSS、JS、字体、logo 和图片不会引用不存在的 `/manus-storage/` 或旧 Cloudflare 资源路径。 | ☐ | |

## 二、逐类页面检查

### 1. 首页 `/`

| 检查项 | 验收标准 | 状态 |
|---|---|---:|
| 页面定位 | 页面标题、主标题和首屏文案清楚说明 ConvertKit 是浏览器本地的单位和格式转换工具。 | ☐ |
| 主功能可用 | 搜索框、热门转换器链接和 Open converter 按钮均能工作；不应让广告遮挡首要操作。 | ☐ |
| 内容深度 | 首屏以下说明隐私、本地处理、支持范围和使用方式；不能只有视觉装饰。 | ☐ |
| 广告预留 | 若使用广告，广告区域与搜索框、导航、转换结果之间有明确间距和标签，不会被误认为工具按钮。 | ☐ |
| 移动端 | 375px 左右宽度下没有横向滚动、遮挡、误触或首屏布局破坏。 | ☐ |

### 2. 单位转换器页面

覆盖 `/meters-to-feet`、`/kg-to-lbs`、`/celsius-to-fahrenheit`、`/liters-to-gallons` 以及各分类页面。

| 检查项 | 验收标准 | 状态 |
|---|---|---:|
| 独立标题 | 页面 H1 明确写出转换方向，例如 “Meters to Feet”，而不是所有页面共用一个标题。 | ☐ |
| 公式说明 | 展示换算因子或公式，并说明结果的舍入和精度规则。 | ☐ |
| 双向使用 | 用户可以理解如何反向换算，或页面提供反向转换入口。 | ☐ |
| 示例内容 | 至少提供一个经过核验的输入、结果和使用场景；示例不能与实际工具行为冲突。 | ☐ |
| 相关链接 | 链接到同类转换器、分类页和指南页，链接文字具有描述性且可抓取。Google 建议使用可抓取链接和描述性文字。[5] | ☐ |
| 错误处理 | 空值、非法值、极大值和非数字输入有清晰提示，不触发下载、弹窗或意外重定向。 | ☐ |
| 广告位置 | 不把广告放在输入框、单位选择器、复制按钮、结果卡片或错误提示的正上方，避免误点击。 | ☐ |

### 3. 格式工具页面 `/format-converters`

覆盖 JSON、CSV、XML、Base64、URL 和 Unix timestamp 工具。

| 检查项 | 验收标准 | 状态 |
|---|---|---:|
| 工具说明 | 页面解释格式转换、验证、压缩或编码的差异，以及输入输出限制。 | ☐ |
| 隐私声明 | 明确说明数据默认在浏览器本地处理；不要在实际未上传时声称服务器端安全处理。 | ☐ |
| 数据边界 | 说明文件大小、字符集、非法输入和大文件处理边界。 | ☐ |
| 下载按钮 | 下载或复制按钮与广告视觉区分明显；广告不能伪装成下载按钮。Google 禁止欺骗性导航和误导性广告实现。[1] | ☐ |
| 错误信息 | 错误内容不包含用户输入的敏感数据，不将错误页面变成广告密集页面。 | ☐ |

### 4. 指南与博客页面 `/blog`、`/blog/:slug`

| 检查项 | 验收标准 | 状态 |
|---|---|---:|
| 原创性 | 每篇文章有实际解释、公式、例子或排错经验，不是批量改写搜索结果。 | ☐ |
| 作者与责任 | 在适合的文章中显示作者、审核者或 ConvertKit 编辑责任信息，并链接到 About 页面。Google 建议让读者知道内容由谁创建。[4] | ☐ |
| 更新时间 | 只有在内容实质更新时才修改更新时间，不要为了制造“新鲜感”而频繁改日期。[4] | ☐ |
| 引用与事实 | 技术、标准和公式有可靠来源或可复核依据；避免未经证实的性能和安全承诺。 | ☐ |
| 文章结构 | 有清晰 H1/H2、摘要、目录或相关链接，结论能直接解决用户问题。 | ☐ |
| 广告密度 | 广告不切断标题、公式、代码、表格或步骤；移动端滚动体验不被插页广告破坏。 | ☐ |

### 5. 法律与信任页面

#### `/privacy`

应说明收集哪些信息、哪些处理在浏览器本地完成、哪些第三方服务被调用、Google AdSense 和广告 Cookie 的用途、个性化广告选择、数据保留、用户权利、联系方式以及政策更新方式。面向 EEA、英国和瑞士用户时，还应把同意管理与撤回方式写清楚。[3]

#### `/cookie-policy`

应按必要 Cookie、分析 Cookie、广告 Cookie 和第三方 Cookie 分类，说明启用条件、保存期限、供应商和撤回方式。Cookie 政策不能只写“我们可能使用 Cookie”，应与实际部署的脚本保持一致。

#### `/about` 与 `/contact`

应让用户知道网站由谁运营、服务的主要目的是什么、如何报告错误或滥用。联系方式必须真实可用，不要放置无人维护的占位邮箱。

#### `/terms`

应说明工具结果的使用边界、准确性限制、禁止滥用、知识产权、服务变更和责任范围。对于单位和格式转换工具，建议明确结果仅供一般信息使用，不替代专业判断。

## 三、广告实现检查

| 检查项 | 验收标准 | 状态 |
|---|---|---:|
| 广告标识 | 广告与工具内容视觉区分明显；不要使用“下载”“开始转换”“结果”等容易误导的标签。 | ☐ |
| 首屏密度 | 首屏不因广告而挤压核心转换功能；移动端尤其避免首屏大面积广告。 | ☐ |
| 交互隔离 | 广告不会覆盖导航、输入框、结果、复制、下载、错误提示或键盘焦点。 | ☐ |
| 不诱导点击 | 不使用“支持我们”“帮助项目”“请点击广告”等文案，不把广告放在箭头、按钮或图片旁造成误认。[1] | ☐ |
| 不弹窗干扰 | 不使用阻断导航的弹窗、弹出窗口、自动跳转或强制下载。Google 要求展示广告的网站易于导航。[1] | ☐ |
| 性能预算 | 加载广告后重新测试 LCP、CLS、INP、移动端速度和布局稳定性；广告容器预留尺寸，避免页面跳动。 | ☐ |
| 失败状态 | 广告没有填充时，页面不显示巨大空白，也不显示破坏布局的错误信息。 | ☐ |
| 测试方式 | 只用广告预览、开发者工具或测试环境验证，不点击真实广告。 | ☐ |

## 四、SEO 与抓取验证

Google Search Essentials 的核心包括技术要求、垃圾内容政策和帮助搜索引擎理解页面的最佳实践。[5]

| 检查项 | 验收标准 | 状态 |
|---|---|---:|
| Title | 每个索引页面都有独立、准确、不过度堆砌关键词的 `<title>`。 | ☐ |
| H1 | 每个主要页面有一个描述性 H1，与页面实际工具和搜索意图一致。 | ☐ |
| Meta description | 描述真实页面功能，不承诺不存在的功能，不批量复制同一段文字。 | ☐ |
| Canonical | canonical 指向规范 HTTPS URL，不指向旧域名、预览域名或带部署查询参数的 URL。 | ☐ |
| Sitemap | sitemap 只包含希望收录的规范 URL，并返回 200。 | ☐ |
| Robots | 不误封首页、转换器、指南和必要静态资源；后台或无价值路由按需要控制。 | ☐ |
| 内链 | 首页、分类、转换器和指南形成清晰的可抓取链接网络。 | ☐ |
| 404 | 不存在页面返回清晰的 404 内容和可用导航；不要把所有错误 URL 当作正常页面。 | ☐ |
| JavaScript 渲染 | 在禁用或延迟 JavaScript 的情况下，页面仍有基本标题、描述和可理解的服务器/预渲染内容；至少验证 Google URL Inspection。 | ☐ |
| 结构化数据 | 只添加真实且与页面内容匹配的结构化数据，不伪造评分、评论、价格或组织信息。 | ☐ |

## 五、隐私、同意和安全验证

在广告脚本上线前，先完成以下验证。若网站面向欧洲用户，不要只依赖静态隐私政策；必须检查实际同意流程是否向 Google 传递相应信号。[3]

| 检查项 | 验收标准 | 状态 |
|---|---|---:|
| 首次访问 | 清除 Cookie 后首次访问，广告和非必要追踪脚本按地区和同意状态加载。 | ☐ |
| 拒绝同意 | 用户拒绝个性化广告后，不应继续按个性化同意状态发送信号；页面仍可使用核心转换工具。 | ☐ |
| 撤回同意 | 用户能够再次打开偏好设置并撤回或修改选择。 | ☐ |
| 供应商列表 | CMP 或隐私页面列出实际使用的 Google 和其他广告技术供应商。 | ☐ |
| 数据最小化 | 转换输入默认不上传；广告和分析脚本不读取或记录用户输入内容。 | ☐ |
| CSP 与安全头 | 部署后检查 CSP、HTTPS、HSTS、X-Content-Type-Options、Referrer-Policy 和权限策略是否与广告脚本兼容。 | ☐ |
| 第三方脚本 | 每个脚本都有明确用途、来源和退出方式；删除过时的 Manus storage、旧广告或调试资源引用。 | ☐ |

## 六、上线前验收流程

| 顺序 | 操作 | 通过标准 | 状态 |
|---:|---|---|---:|
| 1 | 用桌面和移动设备访问首页、单位转换器、格式工具、指南和法律页面。 | 主要路径无错误、无横向滚动、无遮挡。 | ☐ |
| 2 | 使用真实的正常输入、非法输入、空输入和边界值。 | 结果、错误和复制/下载行为符合预期。 | ☐ |
| 3 | 用 Chrome DevTools Network 检查请求。 | 没有旧资源 404、SPA fallback 图片、混合内容或未知广告脚本。 | ☐ |
| 4 | 清除 Cookie 后测试同意流程。 | 同意、拒绝、撤回和刷新后的状态一致。 | ☐ |
| 5 | 运行 Lighthouse 与 axe。 | 没有新的阻断性无障碍问题；广告接入后 Core Web Vitals 不出现明显回归。 | ☐ |
| 6 | 使用 Google Search Console URL Inspection。 | 规范 URL 可抓取、可渲染，robots 和 canonical 没有冲突。 | ☐ |
| 7 | 检查 AdSense 后台站点状态。 | 域名、所有权、付款资料和政策中心没有待处理问题。 | ☐ |
| 8 | 先小范围启用广告。 | 观察 7–14 天的 RPM、填充率、CLS、跳出率和错误日志，再调整广告位。 | ☐ |

## 七、上线后持续监控

每周记录以下指标：广告填充率、页面 RPM、广告请求错误、无效流量提醒、CLS/INP/LCP、移动端跳出率、转换器完成率、404/5xx、robots 变化和 AdSense Policy Center 通知。任何广告布局调整都应先在预览环境验证，再逐步发布。

特别注意：AdSense 收入应服从工具体验。若广告导致用户无法快速完成转换、页面跳动、输入被覆盖或隐私选择不清晰，应优先降低广告密度，而不是追求短期点击率。
