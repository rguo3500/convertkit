# ConvertKit Privacy Policy 的 Google AdSense 合规评估

**评估日期：** 2026-08-17  
**评估对象：** `https://lovexiaoyue.cc.cd/privacy` 及当前 GitHub/main 本地源代码  
**结论等级：** **高风险，不建议现在申请或启用 AdSense**

> **免责声明：** 我是 AI，不是律师；以下是基于当前页面和 Google 公开政策的工作性分析，不构成正式法律意见。涉及 GDPR、英国、瑞士、美国州隐私法或收款税务义务的最终文本，应由合格律师或隐私专业人士审核后使用。

## 一、执行摘要

当前 Privacy Policy **不满足 Google AdSense 上线前的最低准备要求**。生产页面 `/privacy` 目前显示的不是隐私政策，而是占位文案：`This section is structured and ready for the next expansion of the ConvertKit toolkit.` 本地 `client/src/App.tsx` 也将 `/privacy`、`/terms` 和 `/cookie-policy` 路由指向通用 `Placeholder` 组件。

因此，当前页面没有向用户披露 Google AdSense 所需的关键事项，包括广告 Cookie、个性化广告、Google 和其他广告技术供应商、个人数据收集与使用、用户选择权、同意撤回方式、数据保留、跨境传输和联系方式。Google 的 AdSense 政策要求发布商遵守 Google Publisher Policies；Google 也明确要求发布商持续关注政策变化。[1] [2]

当前项目搜索结果中也没有发现 AdSense、`googlesyndication`、Google CMP、Cookie consent 或相关广告脚本。这意味着项目**现在还没有形成实际广告数据处理链**，但这不能替代隐私政策；在接入广告前，必须让页面政策、CMP 配置和实际脚本保持一致。

| 证据 | 当前状态 | 影响 |
|---|---|---|
| 生产 `/privacy` | 显示 “Privacy first” 和通用占位文案 | 用户无法获得实质隐私披露；属于上线阻断项 |
| 本地 `/privacy` 路由 | `Placeholder title="Privacy first"` | 下次部署仍会发布占位页 |
| 生产 `/cookie-policy` | 当前路由结构显示为通用占位页 | Cookie 分类、供应商和撤回机制缺失 |
| 生产 `/terms` | 当前路由结构显示为通用占位页 | 服务边界和责任说明缺失 |
| AdSense/CMP 接入 | 源码未发现 AdSense、Google publisher tag 或 CMP 接入 | 尚未形成广告处理链，但也未准备好合规接入 |
| 本地处理声明 | 转换器页面有“尽可能在浏览器本地处理”的说明 | 这是有益基础，但不能替代完整隐私政策 |
| 联系方式 | Footer 有 Contact 链接，但页面仍为通用占位结构 | 需提供真实且可用的隐私咨询渠道 |

## 三、对照 Google AdSense 要求

| 要求 | 当前判断 | 风险 | 必须补充的内容 |
|---|---|---:|---|
| 隐私政策可访问且内容真实 | **不满足** | 高 | 将 `/privacy` 从占位页改为真实政策；首页/Footer 保持明显入口 |
| 说明广告 Cookie 和本地存储 | **不满足** | 高 | 说明广告 Cookie、类似技术、用途、期限和用户控制方式 |
| 说明 Google 及第三方供应商 | **不满足** | 高 | 列明 Google AdSense/Google Advertising Products 和实际使用的广告技术供应商，并链接其隐私说明 |
| 说明个性化广告 | **不满足** | 高 | 说明个性化与非个性化广告的差异、处理目的和用户选择 |
| EEA、英国、瑞士用户同意 | **不满足/未配置** | 高 | 使用 Google CMP 或其他合规 CMP；按地区获取广告 Cookie 和个性化广告所需同意，并支持撤回。Google 的 EU user consent policy 要求在相关地区进行披露并在法律要求时取得同意。[3] |
| 说明数据收集与使用 | **不满足** | 高 | 说明访问日志、IP/设备信息、分析数据、广告请求数据以及转换输入是否离开浏览器 |
| 说明数据共享 | **不满足** | 高 | 说明 Google、分析服务、托管/CDN、错误监控和其他实际供应商的角色 |
| 用户权利与选择 | **不满足** | 高 | 提供访问、更正、删除、限制、反对、撤回同意和隐私咨询方式；具体范围由适用法律决定 |
| 联系方式与运营主体 | **不满足** | 中高 | 写明运营者名称、隐私邮箱/表单、处理请求的方式和预计响应流程 |
| 数据保留与安全 | **不满足** | 中高 | 说明各类数据的保留逻辑、删除规则和合理安全措施；不要作无法证明的“绝对安全”承诺 |
| 未成年人说明 | **不满足** | 中 | 说明服务是否面向儿童、是否有意收集儿童数据以及发现误收集时的处理方式 |
| 国际传输 | **不满足/待确认** | 中高 | 如使用 Google、Cloudflare、分析或托管服务，应说明可能发生的跨境处理，并由专业人士确认适用机制 |
| 政策更新 | **不满足** | 中 | 提供生效日期、最后更新日期、重大变更通知方式 |

Google 的政策还要求广告实现不误导用户、不鼓励点击、不人为增加展示或点击，并且展示广告的网站应易于导航。[1] 因此，Privacy Policy 合规只是前置条件，广告位置和流量来源也必须单独审核。

## 四、最关键的缺口

### 1. 目前不是“内容不完整”，而是“还没有 Privacy Policy”

当前页面标题虽然叫 “Privacy first”，但实际正文是通用占位文本。Google 审核人员和用户都无法从中判断网站如何处理 Cookie、广告和个人数据。这个问题应作为 **P0 阻断项**，优先于广告代码接入。

### 2. AdSense 相关披露完全缺失

政策至少需要说明：Google 及其合作伙伴可能使用 Cookie 或类似技术投放、衡量和个性化广告；用户可以通过相关设置管理个性化广告；广告技术供应商和相关隐私说明在哪里查看。不要把未经确认的供应商列表直接写进政策，应在 AdSense 后台确定实际选择后同步更新。

### 3. CMP/同意流程尚未建立

如果网站有 EEA、英国或瑞士用户，静态 Privacy Policy 不足以完成 Google 的同意要求。需要实际的同意界面、供应商信息、同意信号传递和撤回机制。Google 官方说明允许使用 Google CMP、第三方 CMP 或自建同意对话框，但实现必须符合其 EU user consent policy。[3]

### 4. 政策、脚本和实际行为必须一致

当前转换器强调本地处理，这是优点，但未来如果接入分析、广告、错误监控或客服工具，就必须重新检查：转换输入是否被读取、哪些请求包含 IP/设备信息、哪些 Cookie 在同意前加载，以及隐私政策是否准确反映这些行为。不能把“本地优先”扩大解释为“网站完全不处理任何个人数据”。

## 五、建议的修订结构

正式政策建议至少包含以下章节，并为每章写明与 ConvertKit 实际行为相符的内容：

1. **运营者与适用范围：** ConvertKit 的运营主体、网站域名、政策适用范围和联系方式。
2. **服务与本地处理：** 单位和格式转换通常在浏览器本地完成；明确哪些功能可能产生网络请求或文件处理。
3. **收集的信息：** 访问日志、IP/设备信息、浏览器信息、错误日志、分析数据、联系表单数据，以及是否收集转换输入。
4. **使用目的：** 提供工具、保障安全、改进服务、统计分析、展示广告、处理用户咨询和遵守法律义务。
5. **Cookie 与类似技术：** 必要 Cookie、分析 Cookie、广告 Cookie 的分类、目的、期限、供应商和管理方式。
6. **Google AdSense 与广告技术供应商：** 实际使用的 Google 产品、广告类型、供应商列表、隐私链接和个性化广告说明。
7. **同意与偏好管理：** EEA、英国和瑞士用户的同意流程、拒绝后的影响、再次打开偏好设置和撤回方式。
8. **共享与国际传输：** Google、Cloudflare、分析服务和其他实际供应商的角色，以及适用的跨境处理说明。
9. **保存与安全：** 不同数据类型的保留逻辑、删除方式和安全措施。
10. **用户权利：** 访问、更正、删除、限制、反对、数据可携带、撤回同意和投诉渠道；按适用地区调整措辞。
11. **儿童隐私：** 是否面向儿童、年龄限制和误收集处理方式。
12. **政策更新与联系：** 生效日期、最后更新日期、重大变更通知和隐私请求邮箱。

## 六、上线前优先级

| 优先级 | 行动 | 通过标准 |
|---|---|---|
| P0 | 实现真实 `/privacy` 页面，而不是 Placeholder | 生产页面有完整正文、更新时间、运营者和联系方式 |
| P0 | 实现 `/cookie-policy` 与 `/terms` | 三个法律页面互相可达，内容不再是占位文案 |
| P0 | 决定是否面向 EEA、英国和瑞士用户展示广告 | 有明确地区策略；若服务这些用户，完成 CMP 和撤回机制 |
| P0 | 在接入广告前确定实际 Google 产品和广告供应商 | 隐私政策供应商列表与 AdSense 后台配置一致 |
| P1 | 为每类转换器补充真实的数据处理说明 | 页面明确本地处理边界，不作绝对隐私承诺 |
| P1 | 用 Network、Cookie 和浏览器存储检查实际行为 | 政策中的 Cookie、请求和第三方脚本与线上行为一致 |
| P1 | 重新测试移动端广告布局和 Core Web Vitals | 广告不遮挡工具、不诱导误点、不造成明显 CLS 回归 |
| P2 | 建立政策变更记录和季度复核 | 记录最后审核日期、供应商变化和 Google 政策变化 |

## 最终判断

当前 Privacy Policy 的合规状态应标记为 **Fail / 不可上线 AdSense**，而不是“部分通过”。原因不是某一条措辞不足，而是生产页面和本地路由仍为占位页，缺失 Google AdSense、Cookie、供应商、同意管理和用户权利等核心内容。

在修复之前，建议**不要申请 AdSense，也不要把 AdSense 代码部署到生产环境**。最合理的顺序是：先完成真实法律页面，再确定广告和 CMP 架构，随后同步隐私政策与实际脚本，最后进行 Google Search Console、浏览器 Cookie/Network、移动端布局和 AdSense 后台检查。
